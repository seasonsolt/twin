# 公开基准生产链路验证与失误分析

记录日期：2026-10-09。本次验证的目的是确认公开基准复用当前 Twin 的生产能力，并定位失误；样本没有随机抽取，不能作为全量成绩或模型排名。

协议为 `production-persona-v1`：合法历史 → 新建隔离 `PersonaStore` → `build_profile` → `index_persona` → `PersonaChat.reply(persist=False)` → 各基准评分。提取、索引与检索保留生产 `target_only=True`；评测回答不写回历史。原始题库、历史、回复、凭证和私有运行产物均在仓库外，本文件只记录汇总和分析结论。

基准的数据版本、合法输入边界和评分规则分别见 [LongMemEval](LONGMEMEVAL.md)、[PersonaMem](PERSONAMEM.md)、[Twin-2K-500](TWIN2K500.md)。旧 `--system retrieval` 的结果不混入生产链路成绩。

本机首轮 LongMemEval 在第一题建档合并时发生一次结构化内容校验失败，未进入回答，后两题被停止机制跳过。随后仅对 LongMemEval 三题做了一次有界补跑，重新建档并全部完成；其他五题未重跑。失败轮和补跑轮的产物独立保留，没有覆盖原始报告。

Twin 分类弃权的计分口径已在运行结束后的独立修复中统一：有标准答案、支持的分类题，成功执行后的无效输出或显式弃权计为错误；真正后端失败、缺失标准答案和无效数值仍保留各自的未评分边界。按修复后的口径，这两条成功弃权记录应为 0/2；这只是口径解释，没有重跑模型或覆盖旧报告。详见 [指标边界](TWIN2K500.md#metric-boundaries-and-outputs)。

## 逐题原因分析

### PersonaMem：回复与正确选项语义重叠，选项提取判错

唯一被官方评分判错的题目要求提供更有满足感的音乐表达方式。回复语义覆盖了正确选项中的写音乐历程、演出和自由享受音乐，但没有输出规定的选项标签，而是自然语言建议。

官方评分器不做语义判断：没有括号选项时，用 `\b([a-d])\b` 从正文提取字母，并要求命中字母集合仅包含正确标签。回复中的英文缩写尾字母和不定冠词导致提取结果同时包含 `a` 和 `d`，因此判错。官方 2/3 成绩必须保留，但现有证据不支持“模型语义选了另一项”的结论。

三题使用同一合法 `context[:182]` 前缀。第三题检索到的用户表达中确有直接相关建议，但表达共 809 字符，直接结论始于约第 730 字符；生产原文呈现只保留前 600 字符，因此该完整尾句没有通过原文通道进入提示。前段仍有间接依据。由于档案条目正文未保留，不能判断模型是否从档案获得了相同事实。

另一条带解释的回复明确给出了括号选项，虽然严格格式检查失败，官方全文回退规则仍判对。因此格式合规率、官方分数与语义分析需要分别报告。

### LongMemEval：已召回的事件与地点没有关联到答案

最终第三题属于 `single-session-user`。问题要求一个优惠券兑换事件的商店地点；同会话已召回的两条本人表达分别包含商店名称和兑换事件，相关表达都很短，没有被 600 字符上限截断。回复保留了优惠券来源，却表示没有使用地点记录，没有回答所需地点。

可排除“相关会话完全未召回”。可能原因包括跨句关系未完成，或生产的严格证据策略将会话关联视为不足；现有记录无法区分。事件那一句本身没有直接标注商店。另一条确认经常在该店购物的本人表达未进入原文召回，可能进一步削弱了关联，但不能将它定为唯一原因。

记录显示 `mode=grounded`、`abstain=false`、confidence 0.98，正文却对所问地点表示证据不足。当前 confidence 表示对本人会这样回答的把握，不是经过校准的事实正确概率；引用 ID 有效也不保证引用覆盖所问字段。

第三题建档和索引无失败。临时库已清理，未保存具体档案条目，因此不能断言事实在抽取或合并时丢失。主模型评委只返回布尔值，未保存判分理由，也没有接收完整历史；能确认回复与标准答案不一致，不能替评委编造具体理由。

### Twin：直接立场覆盖不足；另观察到检索与矩阵呈现限制

两道政策题都没有合法过去问卷中的直接同题答案。过去资料仅有政治倾向和较弱的环保态度等间接背景，不能唯一推出未来的具体分类选择。两个回复均为 `abstain=true`、`mode=abstain`、confidence 0.2，无引用。

政治倾向原文未进入两题的原文召回；是否存在于档案条目中无法确认。环保矩阵虽然被召回，具体陈述首次出现在约第 265 字符，而生产语境只保留前 160 字符，留下泛化题干与回答数组，具体行与答案的对应关系被截掉。这是确定的证据呈现损失，但不能证明档案通道也丢失了含义。

其他原文召回包括人格、花钱习惯和逻辑题等弱相关内容。离线 BM25 支路检查显示选项、格式指令等泛词会竞争原文检索位置；这只是稀疏支路诊断，没有重现完整向量融合排序，不能用它单独解释最终排名。

生产提示要求有明确个人依据才回答，并对不确定是否覆盖的事实保守处理。弃权符合避免冒充本人已表达观点的生产边界，但会降低行为预测任务的覆盖率。修复计分只能纠正报告口径，不能解决证据缺失或提升预测能力。

## 执行失败与内容错误的区分

y15 的 Kimi 验证曾在上游返回 HTTP 503、`auth_unavailable` 时失败；一次诊断明确包含并发额度限制。降到并发 1 后有一次完整单题成功，后续又遇到 503，因此不能认为并发 1 足以保证上游稳定。最近一次 503 未保留完整供应商消息，不能确定仍是并发额度原因。

本机 LongMemEval 首轮失败不同：模型返回 `end_turn`，有完整用量，错误发生在档案细项合并的 Pydantic JSON/schema 校验，没有 HTTP、认证或截断错误。第一轮只保存错误类型，没有具体字段位置，无法继续确定是 JSON 语法、缺字段还是类型不符。

首轮外部脚本把内容错误也设为全局停止，导致后两题未执行，记录为 `budget_skipped`；这是失败停止机制，不是实际费用超限。补跑区分内容校验失败与后端故障：部分建档失败仍不能回答该题，但内容错误不再阻断其他题目。

## 后续改进与分析边界

以下是生产改进方向。第 1 项和第 6 项的结构错误诊断已在本次验证之后实施，其余尚未实施；所有改进都没有为样本修改模型答案：

1. 已实施：Twin 适配器把过去问卷的矩阵行和滑块陈述各拆成一条"陈述: 回答"表达，单选、多选与文本答案改为可读文本；`PersonaChat` 对超过 600 字的表达改为展示与检索问题共享词最多、从句首开始的片段，没有交集时仍取开头。
2. 命中事件后补同会话邻近陈述，保留实体、行为、时间、地点与来源关系；检索突出问题主体，降低选项与格式泛词的权重。
3. 协调自然聊天与评测选项输出契约；保留原始回复及官方评分，另报格式合规率，不用第二模型修答案。
4. 检查回答是否覆盖所问字段，让证据不足的正文、弃权标记和置信度保持一致。
5. 区分有证据的回忆与带不确定性的行为预测，不能把间接背景推测改写为本人已表达事实。
6. 在显式授权的私有诊断中保留最小必要证据呈现和档案引用链。已实施其中的结构错误部分：建档失败记录为错误类型、stop reason 和字段路径（如 `LLMInvalidOutput [stop=end_turn; missing@items.0.statement]`），不含输入或输出正文，评测记录写入 `persona.preparation_failures`。

取证依据为原始合法数据、实际回复、检索 ID、事件日志以及与运行 manifest 一致的源码。可以重建原文 source ID 和截断位置，无法恢复已清理的临时档案、完整提示、向量分数和融合排序。因此抽取遗漏与部分推理原因仍有不确定性。
