# 使用指南

twin 是团队的数字分身：同事把会议录音传进团队录音库，系统认出谁说了什么，管理员按企业邮箱或工号为每位同事建分身，同事登录即认领，点“没问题”之后其他同事才能问。主路径是**团队部署 + 企业 SSO**，见下文「团队部署与登录」；整体设计见 [架构](ARCHITECTURE.md)。

协作者想先在自己的 Mac 上验证，看 [本地快速开始](LOCAL_DEV.md)：运行 `./scripts/local-up.sh`，首次按提示填写模型地址、模型名和密钥，然后在网页「团队」上传会议录音、确认说话人、点「生成分身」。默认开启文字聊天和录音转写，数据在本机 `data/`，与官方演示环境互不影响。

```bash
twin init                     # 生成带中文注释的 twin.toml，按注释填写模型和向量服务
```

模型等后端密钥只放在环境变量里（`TWIN_LLM_KEY`、`TWIN_EMBED_KEY` 等），配置文件只写变量名。企业微信机器人在分身档案页绑定，Secret 保存在分身私有数据目录（见下文）。
可选的 `[chat_llm]` 让聊天（网页、CLI、API/MCP 与评测作答）用更快的模型，档案抽取和构建仍用 `[llm]`；未配置时聊天也用 `[llm]`，示例见 `twin.toml.example`。
外部后端按配置使用，界面如实展示出境分类；用 `twin identity show` 查看，本机转发代理需声明 `egress = "external"`。

## 在 Mac 上常驻部署（可选）

Apple Silicon、macOS 14+ 可在仓库运行 `./deploy/mac/install.sh --dry-run` 预览，再运行安装脚本。
配置后用 `twin doctor` 自检，`twin ops` 管理常驻服务和备份；默认不调用模型，只有 `twin doctor --probe` 才实际探测模型。
默认开启文字聊天和会议录音转写（安装脚本自动安装 `asr-funasr` 包）；朗读真人音色、认人和口型视频默认关闭，按 [媒体配置说明](MEDIA.md) 开启。
当前阶段从本仓库构建 wheel；安装步骤、目录、密钥和恢复说明见 [Mac 部署说明](../deploy/mac/README.md)。

## 网页快速开始

运行 `twin ui`，按打印的本机地址打开页面。管理员（本机模式下就是你自己）默认进入「团队」：

1. **上传会议录音**：在「团队」或「录音库」上传，同一场会重复上传只算一次。转写后系统区分说话人，按声音认出已知的同事。
2. **确认说话人**：拿不准的放在「需要你处理」，就地试听一句，输入是谁，回车确认并跳到下一项。
3. **生成分身**：给某个人点「生成分身」，或在团队页按企业邮箱或工号批量建（见下文）。分身从 TA 在会议里说过的话整理出来。
4. **聊天**：整理完就能和 TA 的分身聊天；也可以给自己建一个分身，按引导介绍自己、加资料。

录音由上传的同事和管理员整理，其他人只能在自己的发言上点「不是我」。各页面的行为见 [网页界面](WEB_UI.md)。

## 团队录音库与分身

**团队录音库**一次部署一个，放在 `data/library/team/`：同事上传的会议录音汇到这里，按内容去重。每段录音归上传的同事，上传人和管理员可以整理说话人，其他人只能在自己的发言上点「不是我」。早期版本每个账号一个录音库，启动时会一次性合并进团队库，原库原样移到 `data/library/.legacy/` 备份，合并规则见 [MEDIA.md](MEDIA.md)。

**团队库**也是一次部署一个，放在 `data/team/team.db`：连起两个人的数据放这里，现在是会话索引（谁问了哪个分身、按哪一档记忆回答；会话正文仍在各分身的库里）。它是各分身库的可重建副本，启动时自动对账，也可以手动 `twin team reconcile` / `twin team reindex`；备份照旧复制整个 `data/`。每条记忆分“同事能用”和“只有本人能用”两档（默认按细项，本人可逐条改），一段会话在建立时就定下按哪一档回答：认领了分身并点过“没问题”的本人是本人档，管理员、建分身的人和同事都是同事档。本人档的会话是和自己的分身说话（对话页里置顶的“我的分身”，只有本人看得到）：它用第二人称答，能用全部记忆和承诺；说“记一下……”记成一条笔记，默认只有本人能用，可以改成同事能用或不存；说了自己答应的事直接进承诺；“看同事会得到什么”按同事档把这一问答一遍，不存。团队库里还有：**团队答案**（本人在“你不在时”里回复几个人问的同一件事时勾选“同时设为团队答案”，或对分身已经用了两次以上的回复点“设为团队答案”；之后谁的分身遇到这个问题都原样引用，标“某某 10 月 22 日确认”，本人之后在会议或对话里说得对不上就标“可能过期”，可以更新、确认仍有效或撤回，撤回后不再被引用）；**这事谁懂**（侧栏“问一句、找人”，⌘K：先给团队答案，再按各人对相关方面的了解程度推荐最多 3 个该问的人——只看“同事能用”的记忆，不推荐你自己、没人认领的和没开放给同事问的分身——再给相关会议）；**助手代问**（在“我的分身”里说“帮我问问王屿和陈一：……”，一次最多 3 位，以本人名义问，每位一段本人的会话；分身答不了、要同事本人定的，要本人点了“转给本人”才会进同事的“你不在时”；只走一跳：被问的分身不会再去问别人）；**赋能**（本人在自己成员页的“赋能”里起名、勾选要借出去的方面——只有看重什么、怎么做决定、怎么思考、擅长什么，且每个方面要了解较多、至少 3 个场合、多是本人原话、来源不止一种、没有矛盾才能勾——再选给全团队还是指定的人；同事聊天时按下“赋能”，这一句就由赋能回答，每条带依据、标明是推测；价格、折扣、审批只提示直接问本人。本人随时可暂停、撤回，能看到赋能被问了什么、说了什么，但看不到是谁问的，也可以纠正，同一方面被纠正三次先停用）。

**每个人一个分身**，每个分身有独立的数据库、素材、任务和聊天记录，位于 `personas/p-<10位hex>/`。顶栏头像可切换分身，列表显示记忆数，可新建、重命名、确认删除（进回收站，7 天内可恢复）；切换停止播放，后台任务继续为原分身处理。

分身的归属都记在数据根目录（`db_path.parent`）的 `personas.json` 里。除 ID、创建时间和默认 ID 外，每个分身有：

| 字段 | 含义 |
| --- | --- |
| `owner` | 建它的账号（管理员或自己建的同事）；null 是旧分身，归管理员 |
| `claim` | 给谁建的：TA 的企业邮箱或工号（SSO 的 account 即工号），不区分大小写；同一个 claim 只能用在一个分身上 |
| `member` | 已认领它的账号。TA 登录时，邮箱或工号与 `claim` 对上就写入，同时记 `claimed_at` |
| `approved_at` | TA 点“没问题”的时间 |
| `public` | 同事能不能问；只有 TA 点“没问题”并勾选“同事能问我的分身”后才为真 |
| `claim_rejected` | TA 点“这不是我”时留下的原 `claim`，提示建它的人邮箱或工号填错了 |
| `by_voice` | 分身是 TA 在同事会议里认出自己声音后建的 |

由团队录音库生成的分身只能私有，直到本人认领并点“没问题”才能对同事开放（`PATCH /api/personas/{id}` 否则返回 409）。

**批量建分身**：管理员在团队页选“按邮箱或工号建分身”，给每位同事填企业邮箱或工号（不知道可以先空着，以后补），系统先用会议为 TA 建好分身。工号和邮箱格式不对返回 400“请输入企业邮箱或工号”，已用在别的分身上返回 409。

**同事这一侧**：用企业账号登录，列表里就出现给 TA 建的分身，页面先显示认领页：看分身整理出的承诺和画像，试聊几句，再选：

- **没问题，开始用**：记下 `approved_at`，勾选“同事能问我的分身”则 `public` 为真；之后同事才能问它。点之前它不对别人回答。
- **这不是我**：分身退回给建它的人，原 claim 记入 `claim_rejected`，团队页的「需要你处理」里出现“分身被退回”，换一个邮箱或工号即可。自己建的分身不能退回。

没有分身的同事登录后先读一句话，在同事上传的会议里认出自己的声音（`#/welcome` 的第一步；已有分身的人从“回去再听一遍”或旧地址 `#/voice` 回到这一步）：只听到每段声音的一句话和会议标题日期，看不到录音、转写稿和别人的发言；确认“是我”后用确认过的发言建分身，会议里没有就建一个空分身自己介绍、加资料。

默认 `[auth].enabled = false` 保持无登录、所有人都是管理员的本机模式。启用登录后，成员能看到自己建的、认领的分身，和别人公开的分身；管理员看全部，列表标出其他拥有者的邮箱。成员默认最多建 3 个分身（`max_personas_per_member`，0 为不限）；认领的分身不占名额。公开分身的访客只能聊天，看不到记忆和设置。

原数据库和 `assets/`、`media-cache/`、`media-sources/`、`uploads/` 原地保留为 `default`，无需迁移。聊天记录保存在各分身的 `twin.db` 里，可搜索、重命名、删除和继续；启用登录后按账号各自私有。默认分身不能删除；有运行或排队任务的分身暂不能删除。CLI/MCP/评测继续使用配置数据库，不新增选择参数。

## 团队部署与登录

Cloudflare Access 已移除，不读取任何 `Cf-Access-*` 身份头；应用本身是认证边界。保持服务只绑定 `127.0.0.1`，Cloudflare Tunnel 或同站反向代理的 HTTPS 域名指向本机端口，并保留原 Host。用 `twin ui --allow-host twin.example.com` 接受自己的域名，不要将开发服务器或本机端口直接暴露到公网。

### 企业 SSO（主路径）

借用同站另一个应用的登录，不发邮件、不用 `[auth.smtp]`；部署示例见 [deploy/daw/README.md](../deploy/daw/README.md)：

```toml
[auth]
enabled = true
provider = "sso"
password_login = true   # 另开 twin 自己的账号密码（twin account add 创建），和 SSO 并列在登录页上
# 管理员按 SSO 账号名或 sso:<subject> 匹配；允许域名里的地址也匹配 @ 前面的账号名
admin_emails = ["zhangxun@xjjk.com"]

[auth.sso]
me_url = "http://127.0.0.1:8765/api/auth/me"   # 带着对方的会话 cookie 询问身份：200 已登录，401 未登录
cookie = "audio_studio_session"
start_url = "/auth/start?next=/twin/"          # 登录页“用享佳统一身份登录”按钮 POST 到这里，由那个应用跳转认证中心
sign_in_origin = "https://center.example.com"  # 认证中心的源，加进 CSP form-action；不写时 start_url 不生效
login_url = "/login?next=/twin/"               # 没有 start_url 时按钮改为链接到这个本站页面
cache_seconds = 60
```

- twin 有自己的登录页：未登录时不再跳走，页面上先是“用享佳统一身份登录”，下面是 twin 账号密码（开了 `password_login` 时）。
- 退出登录同时清掉 twin 的会话和那个应用在本站的会话 cookie，回到 twin 的登录页。认证中心本身没有登出接口，所以再点统一身份登录可能不用重新输入密码。

- 能登录那个应用的人都能进入。twin 取 `me_url` 返回的 `account`（工号）、`display_name` 和 `email`；**目前 SSO 只给 account（工号），暂不给邮箱**，所以现在靠工号认领：管理员建分身时填工号，同事登录时 account 与 claim 对上就认领。SSO 以后带上邮箱，填邮箱也一样能对上。
- 二者都是“企业账号”：认领、在会议里找自己（`#/welcome`）都要求登录身份带邮箱或工号。
- 登录会话由那个应用管理，twin 不存 token；每次请求带着 cookie 询问 `me_url`，结果缓存 `cache_seconds` 秒。

### twin 自己的账号密码

`password_login = true` 时登录页多一组账号密码；只用账号密码、不接 SSO 也不发邮件时写 `provider = "password"`。账号由管理员在服务器上用命令行管理，密码只在终端输入，用 scrypt 加盐存进 `data/auth.db`：

```bash
twin account add zhangsan --name 张三 --email zhangsan@xjjk.com
```

- `twin account passwd <账号>` 重设密码，`twin account remove <账号>` 删除账号，二者都会让它已登录的地方退出；`twin account list` 列出账号。
- 账号的身份是 `user:<账号>`。只有管理员填的 `--email` 用来比对管理员名单和认领分身；账号名本身不和 SSO 的账号名或工号比对，避免同名账号冒充。
- 同一账号 15 分钟内输错 5 次、同一地址一小时内输错 30 次后暂停尝试。

### 邮箱验证码（备选）

没有可借用的 SSO 时，用应用内邮箱验证码：

1. 在 `twin.toml` 配置 `[auth] enabled = true`，填写 `allowed_domains`、`allowed_emails` 和 `admin_emails`（完整示例见 `twin.toml.example`）。域名仅匹配最后一个 `@` 后的完整部分，大小写不敏感；管理员邮箱也须在允许范围内。不写 `admin_emails` 时默认管理员是 zhangxun@xjjk.com 和 qianjinwen@xjjk.com。
2. 配置 `[auth.smtp]` 的 host、port（465 SSL / 587 STARTTLS）、username、from_address、from_name。`password_env = "TWIN_SMTP_PASSWORD"` 只写变量名；通过服务进程的环境安全传入密码，不存入配置或源码。启用登录但缺少 SMTP 配置/密码时启动失败。
3. 重启服务应用配置变更。允许的用户收到 6 位验证码（10 分钟有效、5 次错误后失效）；未允许的邮箱加入等候名单，不发邮件。发送限额：每邮箱 60 秒一次、每小时 5 次，每客户端 IP 每小时 20 次（隧道使用 `CF-Connecting-IP`，否则使用连接地址）。内存限额按进程计算，部署使用单进程。

邮箱登录的账号本身就是邮箱，可直接认领按邮箱建的分身；按工号建的分身只有 SSO 登录能认领。会话默认 30 天，只存于 HttpOnly、Secure、SameSite=Lax cookie（本机 HTTP 开发可非 Secure），不在 localStorage 保存 token。`<数据根>/auth.db` 以 0600 保存验证码哈希、会话哈希及去重的等候邮箱；备份时视作私有资料。管理员登录后可用同源 `GET /api/admin/waitlist` 查看等候名单；放行用户就是把邮箱加入配置 `allowed_emails` 并重启，没有审批 UI。

所有 API/媒体需会话，写操作仍需 `X-Twin: 1`。账号菜单常驻页面，提供“退出登录”。不要在启用 auth 前移除原有外层保护，也不要在公网关闭 auth。

## 记忆上传

```bash
twin persona import 问卷.md 聊天记录.csv 文章/*.md    # 自动识别类型，不用选择
twin persona import 简历.pdf 想法.docx 网页.html
twin persona note "我喜欢先核对事实，再做决定。"        # 写一段笔记
twin persona import --kind interview 访谈.txt        # 可选：明确指定类型
twin persona sources                                # 看已导入的资料
twin persona build                                  # 抽取并合并人格档案，只处理新增或变化的部分
twin persona coverage                               # 看了解到什么，还可以分享什么
```

支持 TXT、Markdown、PDF（文字层）、Word（.docx）、EPUB 电子书、HTML、CSV、JSON、SRT、VTT，自动识别文字编码（含 GBK）；每个文件最多 1 GB，扫描 PDF 暂不支持。日期默认取文件名，聊天缺失日期时取第一条日期，再回退到添加当天。需要强制类型时仍可用 `--kind`。

网页 `#/memories`（导航“记忆”）可以写一段、上传多个文件或整个文件夹，也支持最多 4 GB 的录音、播客、手机视频和屏幕录制。音视频以 8 MiB 分片断点续传；上传时保持页面打开，刷新后重新选择同一文件可继续。原件保留，ffmpeg 提取音频后由 `[asr]` 转写，带时间戳的文字自动进入普通记忆整理。未配置识别也可上传，配置后重启服务，点“重新转写”。命令/HTTP 配置见 [MEDIA.md](MEDIA.md#音视频记忆)。添加、删除后自动处理，不必点构建；可以查看分身看到的文字、记住的条数和失败重试。CLI 导入或笔记保存后，可运行 `twin persona build`，也可启动网页让它自动处理。

## 服务

```bash
twin persona chat "你怎么看远程办公？"
twin ui                                             # 本机网页：多个分身、流式聊天、保存的对话、记忆、朗读与真人视频
twin api                                            # 令牌保护的本机 HTTP API（先设置 TWIN_API_TOKEN）
twin mcp                                            # stdio MCP，供其他工具和 Agent 使用
```

API/MCP 保留高级（advanced）可选参数 `as_of`，评测也保留日期筛选；CLI 和网页聊天不提供它。
配置、接口与隐私规则见 [SERVICE.md](SERVICE.md)。

## 接入企业微信

1. 企业微信 → 工作台 → 智能机器人 → 创建，选择 **API 模式 → 使用长连接**，复制 Bot ID 和 Secret。
2. 打开 `twin ui`，切换到要接入的分身，进入 **档案 → 接入 → 绑定**，填写 Bot ID 和 Secret 后保存。不必修改 `twin.toml` 或重启服务。
3. 「接入」显示连接状态；看到「已连接」后，同事可以单聊机器人，或在群里 @ 它；语音消息也支持（企业微信自动转成文字）。可见范围在企业微信管理后台设置，请只开放给可以查看该分身记忆的同事。

在同一处点击「修改」可更换机器人或 Secret；Bot ID 不变时，Secret 留空表示保持原值。点击「解绑」并确认即可停止连接。只有分身管理者能查看或修改接入设置，公开分身的访客不能访问。

Secret 保存在该分身私有数据目录、与 `twin.db` 同级的 `channels.json` 中（0600 权限；默认分身位于数据根目录），不会返回给浏览器或写入日志。备份时视作私有凭据；删除分身时一起进入回收站，恢复后自动重连。如果机器人已绑定其他分身，恢复的分身会显示冲突，不会抢占连接。

每个机器人只能保持一条长连接，不要用同一 Bot ID 同时运行多个服务，也不能绑定到多个未删除的分身。回复沿用网页聊天的记忆检索与引用核验，聊天上下文仅保存在服务内存，重启后清空。旧配置中的 `wecom.bots` 会被忽略，请在档案页重新绑定。

## 语音与视频（可选）

在 `twin.toml` 的 `[tts]` 里配置语音后端：自托管的 MOSS-TTS-Nano（见 [deploy/tts-moss](../deploy/tts-moss/README.md)）或 Cloudflare MeloTTS（外部服务，按配置使用）。

```bash
twin media speak 回复.json --out 音频目录/            # 分段语音和清单
twin media clip 回复.json --out clip.mp4              # 形象与字幕；需系统 ffmpeg 和中文字体
twin media video 回复.json --out out.mp4              # [video] 通用 SSH 视频任务，见 docs/MEDIA.md
twin media check --out 评测目录/                      # 合成句集回听评测：字错率与延迟
```

网页上可裁剪上传本人照片（JPEG、PNG、WebP、HEIC，最大 15 MB）、录一段声音或上传录音/视频，首次引导也可设置或跳过。
照片用于聊天头像和真人视频；声音用于视频，配置 `[tts].voice_dir` 后也用于听和试听。
素材保存在各分身数据目录的私有 `assets/` 中。只有默认分身可回退到配置的本人肖像和视频驱动素材；
其他分身无照片时使用首字/VRM，无声音时使用 `[tts].voice` 预置音色，真人视频必须先上传该分身自己的照片和声音。
声音处理需系统 ffmpeg；
语音容器需将 `voice_dir` 只读挂载到 `/voices`，见 [deploy/tts-moss](../deploy/tts-moss/README.md)。

视频驱动 JSON 契约新增可选 `portrait`、`voice_ref`：本机为绝对路径，SSH 模式先 scp 到远端 home 的
`.cache/twin-assets/<sha>.<ext>` 后传相对路径。默认分身缺省时驱动沿用自己的素材，其他分身不允许省略素材，完整契约见 [MEDIA.md](MEDIA.md)。

浏览器 3D 形象可在 `[avatar]` 设置 `vrm_path` 指向本地风格化 VRM 文件（不入库）；未配置或加载失败时保留 2D 形象，见 [MEDIA.md](MEDIA.md)。
