# 计划：给声音打标 → 自动归属 → 记忆采集器（2026-10-21）

## 目标

人只给声音打标出人名，系统把相同声线的语音自动归给这个人，把 ASR 文本送进记忆内核。系统承认模型会归错，尽量自动化，并给人留纠偏入口，特别是低置信度的归属。采集器（资料 → 带归属的文本）变了以后，用户可以重新采集。

## 上线门槛（已确认）

| 指标 | 门槛 | 说明 |
|---|---|---|
| 分身里别人的话 | ≤ 5% | **含自动认错**；原来的“自动认错 = 0”取消 |
| 手工处理接入率 | ≤ 10%（按语音时长） | 人需要听并判断的语音占比 |
| 每场确认次数 | 13 人左右的周会 ≤ 约 6 次 | 负责人已接受“每场 5–6 次一键确认”；按人头算，和按时长算的 10% 一起看 |
| 纠错可达性 | 新增指标 | 认错的语音里，有多少排在人物页纠错列表的前 N 条 |

评测用 `twin eval-asr-library`：AliMeeting Eval 8 场用来调参，Test 20 场在冻结后只跑一次。真实效果用 8790 副本复验后，才改生产阈值。daw 线上数据只做只读计数。

## 已有结论（远场本人认领校准，daw 只读跨场检验，2026-10-21）

数据是团队库里负责人确认、出现在两场及以上的 26 个人，用 A 场的声音去认 B 场，共 1807 次；不在场检验 3900 次。

- **同一团队、同一会议室、同一台设备，大家的声纹都偏像，绝对分数靠不住。** 本人最高分中位数 0.636，同场他人最高 0.53，不在场最高 0.478。现行个人认领规则跨场认错约 41%，不在场的人被认领 43%。
- **排名靠得住**：排第一的是本人 79%。所以要看“首选比第二名高出多少”，不看绝对分数。
- **追加认领是最大的错误来源**，即认了最像的一组后再追加其他组。1.4.0 以后，一个人被拆成多组已经很少，追加的收益不抵风险。
- 首选领先 ≥0.1、不追加：认错约 2.6%，待确认约 43%，不在场仍有 15% 被认领。
- **根本办法是把团队库里其他已知人物的声纹当对手**：更像另一个已知的人，就不认。
- 负责人已选（2026-10-21）：个人认领改为首选领先第二名 ≥0.1、不追加。每场约 5–6 次一键确认可以接受。由该 session 实现并验证。

对本计划的影响：

1. 在 AliMeeting 上得到的“`AUTO` 0.5 / 30 秒，手工 27%，认错 0”**不能直接搬到生产**：AliMeeting 每人一个近场麦，声纹天然分得开。阈值必须以“领先第二名”为主，并在 daw 跨场检验上复核。
2. 团队库的自动归属本来就有 `AUTO_MARGIN`，方向一致。但对手只包括**有样本的人**，没样本的人缺席时挡不住别人，所以低档打标要优先问出现最多的声音，尽快把对手集补全。
3. 同一录音里同一个人只自动认一个说话人，其余进中档，对应“不追加”。
4. 个人上传认领（`media/claim.py`）和团队库归属应该共用一套声纹和对手：个人是团队的底座，团队库里认识的人越多，个人认领越准。
5. **中档在 daw 跨场下只有约 59% 是对的**（排第一的本人 1433 次，其中 966 次已被自动认领，剩下约 794 次里首选对的约 467 次），直接进分身会远超 5%。所以中档默认是“一键确认建议人选”，只有 3a 证明在真实数据上达标时，才改成先进分身、后待确认。

## 设计原则

1. 人的工作单位是“声音”，不是“片段”。一个同事在整个库里只问一次。
2. 只有人确认过的声音才能成为声纹样本。自动归属永远不加样本，避免错误自我放大。
3. 人做过的工作不能因为重新采集而丢失。
4. 注意力优先：不开整页、不常驻提示。只在入口加标记，纠错在侧层里完成，关闭后回到原处。

## 阶段 1：采集器版本

采集器分三层，各自带版本，因为重采的成本差别很大：

| 层 | 内容 | 重采方式 |
|---|---|---|
| asr | asr-funasr 包版本（含分离、识别模型） | 在 4090 上重新转写，**用户触发** |
| attribution | `Team.classify` 的阈值、分档、样本策略 | 用已有声纹重新归属，自动，秒级 |
| cleanup | 片段复核（`media/review.py`）、LLM 校对 | 对已有转写重跑，自动 |

- [x] 1.1 参照 `persona/kernel.py` 的 `KernelVersion` / `rebuild_scope`，新增 `CollectorVersion(asr, attribution, cleanup)` 和 `recollect_scope(old, new)`，返回 `none / cleanup / attribution / asr`。
- [x] 1.2 `media/library.py`：转写记录产出它的采集器版本（按现有加列方式追加列）。旧数据标成 `asr ≤ 1.3.3`，版本未知。
  - 已做：asr-funasr 1.4.1 起转写结果带 `version` 和 `pipeline`（如 `1.4.1/overlap`），记在转写文件和 `recordings.asr`。之前的转写（包括 daw 上 1.4.0 转的）一律记为未知，算作比任何已知版本旧；4090 换成 1.4.1 前，线上新转写也是未知。
- [x] 1.3 attribution 记录产出它的归属层版本。
- [x] 1.4 启动时比较版本：归属层或清理层变了就自动排队重跑；asr 层变了只标记“可重新采集”。
  - 已做：按新规则重判旧规则做出的自动决定，结果不变的只改版本，不关闭分身。清理层只重判自动排除的片段；复核自动改给别人的说话人保留不动，因为那一步同时停用了样本，由负责人撤销。LLM 校对每份转写只做一次，不随清理层版本重跑（会花额度），换转写后自然重做。
- [x] 1.5 测试：版本比较、迁移，以及旧库打开后不中断。

## 阶段 2：重新采集时保住人做过的工作

- [ ] 2.1 重新转写时先保留旧转写：新转写就绪后切换，可以回退，做法和内核快照一样。

## 风险

- **认错的语音进分身后会污染记忆**：中档默认先确认再进分身；高档的少量认错靠 5% 门槛、纠错入口和样本战绩降权三层兜底；不达标就不放宽。
- **AliMeeting 不代表真实周会**：近场麦让声纹天然分得开，daw 跨场检验显示同屋声纹偏像、现行个人认领认错约 41%，所以以 daw 跨场计数为准，AliMeeting 只作不退化对照。
- **重新转写占用 4090**：排低优先级，一次一个，避开 audiostudio 的高峰。
- **说话人编号变化时标签迁移失败**：失败的进入纠错列表，不静默丢弃；旧转写可以回退。
