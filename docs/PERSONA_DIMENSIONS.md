# 人格复刻维度与完成度（v0）

状态：设计稿，2026-10-03 与项目负责人讨论后确定方向，细节可继续调整。

## 1. 目标与原则

- **通用个人分身**，以身份、记忆资料与服务为主线，不预先限定单一业务场景。
- **维度清晰、可度量**。每完成一个采集阶段，都能回答两个问题：每个维度复刻到了什么程度；下一步最该采集什么。
- **证据优先**。每条结论都挂着可核对的原话和日期，并标注来源是"实际行为"还是"本人自述"。
- **隐私分级**。个人生活类维度默认不采集，本人逐项授权后才采集；对具体他人的评价不进档案。L1 所有来源一律保存原文与真实发言人；按 `pseudonymize_others`，在语料进入 L2 抽取、L3 向量化与 PersonaChat 展示时统一生成化名视图（含语境、说话样本与引文），不改写语料。本人姓名及别名保留，他人姓名以原始语料中出现的非本人发言人为已知姓名表，跨来源一致替换；不猜测仅在散文中出现的未知姓名。旧来源缺少 `text_state` 标记时视为已化名，不二次处理；新来源写 `raw`。旧库遗失的真名不能恢复，须有原始文件才能重新导入。

## 2. 维度体系

共 9 个维度，39 个细项。细项是计算完成度的最小单位，编号写进每条认知条目。

| 维度 | 细项 | 变化速度 | 授权 |
| --- | --- | --- | --- |
| D1 身份与经历 | 1.1 角色与职责；1.2 履历与关键转折；1.3 常讲的经历与故事；1.4 所在组织与协作关系（只记结构，不记评价） | 慢 | 默认 |
| D2 价值观与原则 | 2.1 核心价值排序；2.2 底线与红线；2.3 做事与经营原则；2.4 对人的基本假设（信任、授权观） | 慢 | 默认 |
| D3 决策与判断 | 3.1 风险偏好；3.2 时间视角；3.3 依据偏好（数据、直觉、经验、他人意见）；3.4 常见取舍；3.5 各领域立场；3.6 决策节奏与授权（何时当场定、何时延后、交给谁） | 中 | 默认 |
| D4 思维方式 | 4.1 拆解问题的方式；4.2 追问习惯；4.3 常用类比与思维模型；4.4 对不确定性的处理 | 慢 | 默认 |
| D5 知识与专长 | 5.1 专业领域；5.2 行业判断；5.3 自认不懂的领域 | 中 | 默认 |
| D6 表达风格 | 6.1 用词与口头禅；6.2 句式与结构；6.3 修辞（比喻、算账、讲故事）；6.4 对象差异（对上、对下、对外）；6.5 书面与口头差异 | 慢 | 默认 |
| D7 人际与情绪 | 7.1 对上；7.2 对下（辅导、授权、表扬、批评）；7.3 对平级与外部；7.4 冲突处理；7.5 情绪触发与压力反应 | 中 | 默认 |
| D8 当前状态与关注 | 8.1 近期重点；8.2 手头项目与进展；8.3 最近在想或纠结的问题 | 快 | 默认 |
| D9 个人生活与偏好 | 9.1 兴趣爱好；9.2 生活习惯与作息；9.3 家庭（仅本人愿意公开的部分）；9.4 健康与运动；9.5 品味偏好（饮食、阅读、音乐等） | 慢 | **逐项授权** |

人格条目直接使用细项编号，并附来源证据；本人可以审核其表述。

维度体系做成独立、带版本号的配置文件。改版时，旧版本的完成度报告保持可复现。

## 3. 证据与来源

每条证据记录：原话、日期、来源类型、场合（对谁、什么场合、在回应什么）。

| 来源类型 | 归类 | 示例 |
| --- | --- | --- |
| 会议转写 | 实际行为 | 交流、一对一、访谈转录 |
| 聊天记录 | 实际行为 | 飞书、钉钉、微信工作群 |
| 文档与邮件 | 实际行为 | 方案、周报、邮件、审批批注 |
| 问卷 | 本人自述 | 本文第 6 节的问卷 |
| 访谈 | 本人自述 | 针对缺口和矛盾的定向访谈 |
| 传记与他人记述 | 实际行为（他人转述） | 传记、年谱、报道；只有引文里本人说的话算原话 |

传记类资料是别人的第三人称叙述：叙述作为行为证据，作者的评论不算本人想法；抽取时标出哪些引文是本人原话，\
表达风格类细项（6.x）只能依据本人原话，没有聊天记录时口吻样本也取自这些原话。

同一细项上，自述和行为方向相反时，记为**矛盾**。矛盾不自动裁决，进入访谈清单，由本人解释或审核时决定。

## 4. 完成度定义

每个细项分三层，逐层递进。

### 4.1 覆盖 C ∈ {0, 1}

至少有一条未被否决、引文核对通过的认知条目，记 1。

### 4.2 充分 S ∈ [0, 1]

```
S = 0.5 × min(1, 不同场合数 / k)
  + 0.25 × [有实际行为证据]
  + 0.25 × [证据来自至少两类来源]
```

- 不同场合数：按场次、会话、文档计数，同一场会里说十遍只算 1。
- k：默认 3，按维度可调。
- D8（当前状态与关注）只计最近 90 天的证据。
- 有未解决的矛盾时，S 封顶 0.5。

### 4.3 准确 A ∈ [0, 1] 或"未测"

用标注了该细项的测试题实测：

- 本人盲答：分身与本人答案的一致率，除以本人前后两次作答的一致率（即本人重测一致率）；
- 熟人评分：熟悉本人的同事盲评"像不像"；
- 个人情境题：针对该细项的独立留出问题。

测试题少于 3 道时记"未测"，不参与汇总。

### 4.4 细项等级

| 等级 | 条件 |
| --- | --- |
| 0 未覆盖 | C = 0 |
| 1 已覆盖 | C = 1，S < 0.7 |
| 2 充分 | S ≥ 0.7 |
| 3 已验证 | S ≥ 0.7 且 A ≥ 0.7 |

### 4.5 维度汇总

每个维度报告三个比例：覆盖率、充分率、验证率（分别为等级 ≥ 1、≥ 2、= 3 的细项占比），以及未解决矛盾数。v0 按细项等权平均；需要时再引入细项权重，例如决策类高、生活类低。

## 5. 每个采集阶段的输出

每个阶段结束时生成一份完成度报告，包含：

1. **维度汇总表**：9 个维度的覆盖率、充分率、验证率、矛盾数。
2. **细项 × 来源矩阵**：每个格子是证据场合数，空格一眼可见。
3. **下一步采集建议**：列出未覆盖、不充分、有矛盾的细项，并按"哪类来源最可能补上"排序。例如 9.x 只能靠问卷和访谈，6.4 需要聊天记录里对不同对象的发言。

采集顺序按缺口驱动：

| 阶段 | 做什么 | 主要补哪些维度 |
| --- | --- | --- |
| ① 问卷 | 本人填写，40–60 分钟 | 全维度铺底（自述），D1、D9 最依赖 |
| ② 被动语料 | 会议、聊天、文档、邮件 | D3、D4、D6、D7、D8 的行为证据；暴露自述与行为的矛盾 |
| ③ 访谈 | 只问矩阵里的空白和矛盾 | 定向补缺 |
| ④ 测试 | 本人盲答、熟人评分、个人情境题 | 把"充分"推进到"已验证" |

## 6. 问卷设计

- 30–40 题，约一半是**情境判断题**：给一个具体情况，问会怎么做、会怎么说（请写出原话）。同一道题同时采到判断和口吻。
- 每题标注所属细项和题型（情境判断、开放自述、偏好选择）。
- **测试题与建档题分开**：约三分之一的情境判断题只用作测试，不进档案，否则用来建档的答案又拿来测分身，等于泄题。
- D9 的题目都可以跳过；跳过即视为不授权该细项。

## 7. 对架构的影响

- **通用内核**：
  - 统一的"表达"数据单位（谁、何时、什么场合、原文），各类来源用转换器转成这个格式；
  - 认知条目带细项编号和来源类型；
  - 新增完成度计算模块，以及报告的命令行和网页视图。
- **接入**：CLI 和本地网页提供问卷、资料导入、档案审核、完成度与聊天；具体服务场景以后按通用契约扩展。
