# 计划：团队版第一步 · 纯界面改造（2026-10-22）

团队版分两步做。第一步只用后端现有的接口，把第 1–9 屏换成新设计，加上第 10 屏“你不在时”的第一版；不加接口、不动数据库和记忆内核。第二步（团队级的库、转交、我的分身、团队答案、赋能等）另立计划。

设计依据是设计总稿“twin 团队版 · 设计总稿”里的“实现计划”画板和第 1–10 屏，以及第 6、10 屏的第一步版本（画板 6′、10′）。两者不一致时以设计稿为准，并回来改这份文档。

## 规矩

- **后端零改动**：不加接口、不改数据库和内核。每期合并前确认 `src/twin` 下除 `web/static`（前端构建产物）外没有改动：

  ```bash
  git diff --stat main -- src/twin ':!src/twin/web/static'
  ```

- **现有接口给不出的就去掉**：不放占位，不写“即将上线”，第二步再补。
- **能留的原样留**：已经和设计一致的组件不重写，只换位置或文案；设计没画、但现在在用的功能不删，在下面的逐屏表里写明去处。
- **一个提交一件事**：尽量不超过 8 个文件。要拆的文件先单独提交拆分，外观和截图都不变；下一个提交再改样子。
- **每期都能单独上 stable**：老入口在新入口上线的那一期才拿掉，旧地址自动跳转。没做完的新界面放在管理员的功能开关后面。
- **界面规则照 `AGENTS.md`**：只用 `components/ui` 的组件，缺组件先加进 `components/ui` 并在 `#/gallery` 展示；少字、低密度。

## 已定的四件事（10-22）

1. **访客怎么判定**：管理员，或名下有能管理的分身，就不是访客；其余登录的人是访客，侧栏只有“对话”。现在的 `useCanManage`（`stores/personas.ts`）只看当前分身，要改成看全部分身。
2. **不在录音库里的分身**：自己建的、别人公开的分身，和录音库里的人并成团队表的一张表，一样能进成员页。这些分身的成员页暂用 `#/team/twin/:分身编号`，第二步补齐 `people` 后再跳到人的编号。
3. **设计没画的待处理事项**：现有八类都留在 `#/inbox`。设计画了三组；其余五类（还没认人、转写失败、可能是同一个人、有人说不是自己、分身被退回）有事项才显示，空的不显示。逐个听只走“新的声音”。
4. **撤销用延迟提交**：点了以后，这一行先变成“已归给王屿 · 撤销”，几秒后收起时才提交；离开页面前把没提交的都提交。删除录音不在此列：删了不能恢复，仍要确认。
